# Проверка ШАГРЫ для жюри

Приложение запускается локально из репозитория. Публичный сервер и домен для проверки не предоставлены. Все демонстрационные профили и история синтетические.

Эта инструкция описывает самостоятельный запуск по [п. 5.4.16 правил](../rules.md) и способы проверки без личных аккаунтов и подписок эксперта по [п. 5.6.6](../rules.md). Для проверки живого AI выберите OpenAI с предоставленным командой тестовым ключом или локальную Ollama. Подготовленный офлайн-режим позволяет проверить основной рабочий процесс и резервный подбор по правилам.

## Выбор режима

| Режим | Что потребуется | Какой результат проверять |
|---|---|---|
| OpenAI, живой AI | Интернет и тестовый API-ключ от команды | Рекомендация с `source=llm` |
| Ollama, локальный AI | Ресурсы для модели; интернет для первой загрузки | Рекомендация с `source=llm`; при ошибке возможен fallback |
| Подготовленный офлайн | Docker и зависимости, скачанные при сборке | `source=deterministic_fallback`, в интерфейсе «По правилам» |

Для Docker нужен работающий Docker Engine/Desktop и Compose v2. Все команды выполняются из корня репозитория. Первая сборка требует интернета даже для офлайн-режима. Если Docker недоступен, используйте [нативный запуск из README](../README.md#установка-на-разных-системах). При прямом запуске Python/uvicorn файл `.env` **не загружается автоматически**: переменные нужно передать в окружение процесса.

## 1. OpenAI: живые рекомендации

Создайте `.env` из [.env.example](../.env.example), если файла ещё нет; существующий файл не перезаписывайте. Укажите:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=<тестовый ключ, переданный командой приватно>
APP_PORT=8080
APP_ORIGIN=http://localhost:8080
```

Тестовый ключ передаётся отдельно от репозитория. Эксперту не нужен личный аккаунт OpenAI или подписка; доступ и доступный лимит API обеспечивает команда. Ключ хранится только на серверной стороне: не добавляйте его в Git, материалы презентации или `VITE_*`.

```bash
docker compose up -d --build app
docker compose ps
```

Откройте [localhost:8080](http://localhost:8080) и [health](http://localhost:8080/api/v1/health). Проверьте источник текущей рекомендации: `source=llm` подтверждает принятый ответ модели, а `deterministic_fallback` означает резервный расчёт. Отсутствие ключа, исчерпанный лимит, недоступность или некорректный ответ модели приводят к fallback; работающий HTTP-сервер сам по себе не подтверждает живой AI.

## 2. Ollama: локальный AI без аккаунта

В `.env` задайте:

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://ollama:11434
OLLAMA_MODEL=qwen2.5:1.5b
APP_PORT=8080
APP_ORIGIN=http://localhost:8080
```

```bash
docker compose --profile local-ai up -d --build
docker compose logs -f model-init
```

Сервис `model-init` скачивает выбранную модель в постоянный том. Дождитесь завершения загрузки; затем откройте [localhost:8080](http://localhost:8080) и проверьте источник рекомендации. На время загрузки и при ошибках доступен подбор по правилам. Скорость зависит от оборудования и модели. Этот режим не проверен в текущем аудите; задержка менее 10 секунд не гарантируется.

## 3. Подготовленный офлайн-режим

Запуск использует [отдельную конфигурацию](../config/jury-offline.env), [Compose override](../compose.offline.yaml), проект `shagra-jury` и отдельный том данных:

```bash
docker compose --env-file config/jury-offline.env -p shagra-jury -f compose.yaml -f compose.offline.yaml up -d --build app
```

Откройте **[localhost:8081](http://localhost:8081)** и [health](http://localhost:8081/api/v1/health). Конфигурация принудительно задаёт пустой API-ключ и нулевой лимит платных вызовов. Это детерминированный подбор по правилам; живой LLM в этом режиме не вызывается. Можно проверить профиль, рекомендации, примерку, сравнение, выполнение, историю и HR-импорт.

Повторный запуск сохраняет состояние тестового тома, включая выполненные активности и импорты. Поэтому значения после первого показа могут измениться. Удаление тома уничтожает эти данные; сброс допустим только для отдельного тестового проекта после осознанного решения оператора.

## Сценарий проверки

Если демонстрационные пароли не изменены в конфигурации:

| Роль | Логин | Пароль |
|---|---|---|
| Сотрудник E0001 | `employee` | `demo-employee` |
| HR | `hr` | `demo-hr` |

1. Войдите сотрудником. Проверьте текущий и целевой грейд, карту навыков, покрытие требований и источник рекомендации. Раскройте «Почему этот шаг»: объяснения должны содержать цель, разрыв навыка и факты истории.
2. Нажмите «Примерить шаг» и включите сравнение. Сопоставьте уровни и покрытие до/после. Закройте примерку: профиль и история должны остаться прежними. Конкретный прогноз зависит от выбранной активности и текущего состояния БД.
3. Снова откройте примерку и подтвердите фактическое выполнение. Проверьте обновлённые навыки, историю и рекомендацию. Покрытие требований — расчёт навыков, а не решение о повышении.
4. Выйдите и войдите как HR. Откройте сводку, поиск сотрудника и подробные таблицы участия и дефицитов.
5. Перейдите в импорт и загрузите оба готовых файла: [employees.json](../data/demo-import/employees.json) и [activity_history.csv](../data/demo-import/activity_history.csv). Это четыре синтетических профиля: активный, с достигнутой целью, с последним грейдом и без одной оценки. CSV содержит заголовок без записей истории. Сначала нажмите проверку, изучите количество изменений и ошибки; применяйте только валидный результат. Затем найдите импортированного сотрудника по ID из файла.

Поле `role` в примере сопоставляется с ID или доступным названием роли из текущего каталога с удалением внешних пробелов и без учёта регистра. Каноническое поле `role_id` также поддерживается. Неизвестные или неоднозначные роли и конфликт между `role` и `role_id` отклоняются; произвольные форматы не угадываются. Совпавший ID сотрудника означает полную замену профиля, включая навыки. Импорт истории не начисляет эффекты повторно. [Подробности формата](DATA.md).

## Что подтверждено проверками

[Результаты и хэши проверенных исправлений](validation/jury-readiness.json).

Независимый чистый нативный прогон с Python 3.12 и Node.js 24 подтвердил сборку. Повторный прогон с исправлениями: 64 backend-теста и 18 HTTP-проверок, включая импорт `role` и читаемые объяснения. Запуск Docker в текущей среде аудита заблокирован правами на Docker socket; этот результат не является подтверждением контейнерного запуска. Браузерная проверка на отдельной БД без ключа подтвердила вход, явную отметку «По правилам», исправленные объяснения, примерку и подтверждение выполнения.

[Повторная проверка Q1–Q3 OpenAI](validation/jury-openai.json) содержит исторические результаты реальных вызовов модели с датой, ревизией и `source=llm`. Он не подставляется вместо ответа API и не доказывает доступность модели при новом запуске. Текущий режим оценивайте по фактическому ответу рекомендации. Дополнительные команды и ограничения — в [TESTING.md](TESTING.md) и [AI.md](AI.md).
