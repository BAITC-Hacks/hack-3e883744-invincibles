# ШАГРА: пакет заданий для трёх агентов

Это разделение согласованной концепции на рабочие пакеты в составе проектного ТЗ. Исходный код ещё не реализован. Все агенты обязаны прочитать [основную спецификацию](../superpowers/specs/2026-09-23-shagra-design.md); её схемы и правила имеют приоритет над краткими заданиями.

1. [Агент 1: кит, ядро, API, запуск](agent-1-data-api.md).
2. [Агент 2: рекомендации и доказательство работы AI](agent-2-recommendations.md).
3. [Агент 3: интерфейс, проверки и сдача](agent-3-ui-delivery.md).

Один координатор сохраняет границы файлов, интегрирует коммиты последовательно и следит за пятичасовым окном. Три агента не запускаются самим фактом написания этих документов.

## Общий порядок

Первые 20 минут: А1 выпускает contracts и примеры, А2 проверяет модель/готовит контрольные профили, А3 собирает UI и HTTP-типы. После этого потоки независимы по редактируемым файлам и работают через контракт. Полная интеграция обязательна к минуте 180, не к минуте 290.

Каждый час есть проверяемый результат в официальном репозитории. Перед общим commit проверить, какие файлы принадлежат текущей задаче; не добавлять чужие изменения командой git add . без просмотра.

## Общие запреты

- Не заменять неизвестные значения нулями и не угадывать схему официального датасета.
- Не выдавать fallback за LLM, синтетику за данные банка, покрытие навыков за вероятность повышения.
- Не менять контракт и lock-файл другого агента самостоятельно.
- Не добавлять чат, валюту, календарь, vector DB, agent framework и другие исключённые функции.
- Не проводить завершающие проверки только на mocks: нужны живой backend, реальная модель и чистый запуск.

## Единый формат отчёта агента

Поставлено: функции и файлы. Проверено: команды, результаты, SHA и условия. Не закрыто: точный критерий/ошибка. Для интеграции: изменившиеся поля/параметры, если есть. Следующий владелец: кому нужен результат. «Готово» допустимо только при выполненной приёмке своего пакета.
