# A2 — рабочий HR-интерфейс и импорт

## Готовый промпт агенту

Ты — A2. Реализуй HR-обзор и импорт ШАГРЫ в новом тёмном дизайне с настоящим API. Итог должен работать внутри общего React-приложения. Не создавай отдельное приложение или статический предпросмотр.

Сначала прочитай [общий план](../superpowers/plans/2026-09-23-production-redesign.md), [требования](frontend-design-requirements.md), [референс](a3-template.jpg), HR-макеты `docs/validation/ui/redesign/`, текущие HrPage/ImportPage в `frontend/src/App.tsx`, `api.ts`, `types.ts`. Общие компоненты поставляет A1; API-поля role_name — A3. Прочитай интерфейсы §3 общего плана до начала.

## Задача 1. HR-сводка и поиск

**Файлы:** `frontend/src/pages/hr/HrOverviewPage.tsx`, `frontend/src/features/hr/*`.

**Входы:** `api.overview(signal)`, `api.employees(q, offset, limit, signal)`; типы HrOverview/EmployeeList с role_name.

**Выход:** default-export HrOverviewPage без собственной оболочки/меню. Ссылки на профили — `/employees/:id`, импорт — `/hr/import`.

- [ ] Создай экран из общих Panel/PageHeader/Stat/Field/Button; используй tokens A1, не добавляй собственную светлую тему.
- [ ] Покажи employees_total, число no_catalog_coverage, число incomplete_skills. Не суммируй affected_count разных навыков как число уникальных сотрудников.
- [ ] Построй топ-5 по affected_count desc с tie-break по названию; укажи assessed_count и affected_share. Числа берутся из API.
- [ ] Покажи распределение всех причин no_step; финальный грейд и покрытые требования не окрашивай как ошибки.
- [ ] Поиск по ID работает на любых существующих ID, включая только что импортированный профиль. Используй role_name.ru/en, без словаря BACKEND/DATA_ANALYST из макета.
- [ ] Отменяй устаревший поиск, не показывай ответ старого запроса поверх нового. При сбое overview/search отображай соответствующую ошибку и retry.

## Задача 2. Таблицы и мобильная версия

**Файлы:** `frontend/src/features/hr/HrDataTable.tsx`, `hrTableState.ts`, локальные CSS Modules.

- [ ] Вкладки: дефициты, без шага, участие. Query `tab=gaps|no-step|participation`; поиск `q`; сортировка `sort` и `dir=asc|desc`; страница `page`; размер `size=10|25|50`.
- [ ] Некорректные query безопасно нормализуй: tab=gaps, page=1, size=10. На изменении фильтра сбрасывай page=1; после фильтрации ограничивай page последней доступной страницей.
- [ ] Начальный sort: gaps — affected_count desc; no-step — employee_id asc; participation — completed desc. Вторичный ключ — название или ID asc.
- [ ] Имена/ID сортируй как текст, числовые поля — как числа. null всегда в конце и отображается «нет данных»; 0 остаётся нулём. Для unknown reason показывай нейтральное «Причина не распознана», не внутренний код.
- [ ] Поиск выполняй по отображаемым полям текущей вкладки. Клиентская пагинация работает по полным массивам overview и не выдаётся за серверную.
- [ ] На телефоне ключевые показатели помещаются в компактные строки с раскрытием; полная таблица имеет локальную горизонтальную прокрутку. Не растягивай body.
- [ ] Сортировка — настоящая доступная кнопка в заголовке с aria-sort на th. Пагинация и фильтры доступны клавиатурой, пустой результат имеет понятный reset.

## Задача 3. Проверка и применение импорта

**Файлы:** `frontend/src/pages/hr/HrImportPage.tsx`, `frontend/src/features/import/*`.

**Входы:** неизменённые `api.validate(employeesFile, historyFile)`, `api.commit(importId, version)`, ImportValidation/ImportCommit. Существующий импорт в App.tsx использовать как функциональную основу, не упрощать его гарантии.

- [ ] Реализуй последовательность файлы → проверка → применение. До validate не держи большую пустую панель результата.
- [ ] Показывай имена и размеры, два обязательных файла и лимит 5 MiB. File input работает клавиатурой. Не обещай drag-and-drop без реализации.
- [ ] Смена файла сбрасывает результат validate/commit. Результат предыдущего validate, пришедший после смены файлов, игнорируется по ID запроса/снимку выбранных файлов.
- [ ] Покажи summary, file/path/code/message ошибок и явное предупреждение о полной замене снимков. Для списка новых/заменяемых ID используй реальный список сотрудников с пагинацией, не только первые 50.
- [ ] Если получение текущих ID не удалось, не выдумывай новые ID; summary сервера остаётся источником количества, рядом объясни недоступность списка.
- [ ] Commit доступен только для текущей успешной проверки; пока идёт запрос, повторное действие отключено. 409/410 сбрасывают проверку и требуют validate заново.
- [ ] При сетевом сбое commit сохраняй import_id/version для безопасной повторной попытки. Ответ applied=false означает уже применённый импорт, а не ошибку.
- [ ] После успеха покажи результат и ссылки на новые профили; для замен — переход к поиску/профилям без hardcoded ID.

## Задача 4. Проверки и передача

**Тесты:** `frontend/tests/hr-redesign.spec.ts`, `frontend/tests/fixtures/hr-redesign.ts`.

- [ ] Fixtures включают role_name, 0, null, длинное название, разные знаменатели, более 25 строк и все причины отсутствия шага.
- [ ] Проверь поиск произвольного ID, сортировку чисел, query после reload/back, сброс страницы после фильтра и мобильный overflow.
- [ ] Проверь validate с ошибкой последней CSV-строки: кнопки применения нет; импорт не вызван. Проверь предупреждение о замене и успешный commit.
- [ ] Проверь гонку: validate A задержан, пользователь выбирает B, ответ A приходит — применить A невозможно. Проверь 409/410 и повтор commit после сетевой ошибки.

```ts
// После успешного validate и смены employees-файла:
await expect(page.getByRole('button', { name: 'Подтвердить и применить' })).toBeHidden()
// На мобильном HR/импорте:
expect(await page.evaluate(() =>
  document.documentElement.scrollWidth - document.documentElement.clientWidth
)).toBeLessThanOrEqual(1)
```

- [ ] Выполни `npm --prefix frontend run build` и `npm --prefix frontend run test:e2e -- tests/hr-redesign.spec.ts` после получения общего UI A1.
- [ ] Передай A1 SHA с HrOverviewPage/HrImportPage для подключения; не редактируй App.tsx самостоятельно.
- [ ] Пройди импорт через настоящую тестовую среду A3; передай ему снимки HR/import на 390 и 1440 px и результаты.

**Готово:** HR видит реальные показатели и любой профиль; импорт действительно проверяет/сохраняет данные; все состояния оформлены общей темой. Никаких window.SHAGRA_DESIGN и демонстрационных onclick. Не редактируй shared UI, lockfile, backend и общие тестовые конфиги.
