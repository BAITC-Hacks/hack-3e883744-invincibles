# Агент 3 — интерфейс, пользовательский сценарий и сдача

Обязательное чтение: [ТЗ ШАГРА](../superpowers/specs/2026-09-23-shagra-design.md), особенно §3–4, §9–10, §13–17. **Цель:** пользователь проходит полный сценарий, а эксперт самостоятельно запускает и проверяет продукт.

## Владение

Весь frontend и его lock; README.md; THIRD_PARTY.md; docs/DEMO.md; результаты браузерных проверок в docs/validation/ui. Не редактировать backend, contracts, Dockerfile, compose и Python зависимости.

## Поставки и критерии

### A3.1. Каркас и чтение профиля — до 60 минут

- [ ] Создать Vite/React/TS + Tailwind CSS 4 через @tailwindcss/vite; импорт Tailwind и @theme, token-цвета и breakpoints из §3. Повторяющиеся элементы — React-компоненты, никаких runtime CDN и динамически склеенных class names.
- [ ] Описать типы и fetch wrapper по §9–10; credentials=include, общий разбор API-ошибок, AbortController для отмены устаревшего UI-запроса.
- [ ] Начать с login и /me; HR-страницу открывать по серверной роли /auth/me.
- [ ] Подключить profile fixture из contracts/examples; mocks живут в Playwright route interception, не в production client.
- [ ] Создать таблицу навыков/историю и карточки рекомендаций. Запрос AI не блокирует профиль.

Доказательство: сборка проходит; на fixture видны цель, уровни и история; отсутствующий навык не превращается в ноль.

### A3.2. Примерка и выполнение — 60–120 минут

- [ ] PreviewPanel вызывает API, показывает before/after/remaining gap/coverage; не присваивать after основному профилю.
- [ ] Сравнение вызывает два preview по одинаковым версиям; если один устарел, обновить оба.
- [ ] Показывать обязательные evidence и раскрываемые refs; source=deterministic_fallback имеет явную подпись.
- [ ] Completion: подтверждение, UUID Idempotency-Key на операцию, disabled на время запроса; при сетевом retry сохранять тот же ключ и исходное тело.
- [ ] После успеха обновить profile/recommendations и закрыть устаревшую примерку. После 409 показать сообщение и перечитать профиль; автоматически не повторять изменение с новыми версиями.
- [ ] «Другой вариант» меняет только excluded_event_ids в локальном состоянии и повторяет recommendations. При смене профиля исключения сбрасываются.

Доказательство: preview не меняет профиль; повторный клик не создаёт вторую операцию; source/status различимы без технической консоли.

### A3.3. HR и импорт — 120–180 минут

- [ ] Реализовать три таблицы §3.2: понятные знаменатели, «нет данных» вместо 0/0, последние грейды отдельной информационной категорией.
- [ ] Поиск по ID открывает /employees/:id; HR может подтвердить выполнение с явной подписью своей роли.
- [ ] /hr/import принимает два файла, показывает validate-результат, список замен и предупреждение о полной замене snapshot; только затем commit.
- [ ] Показать file/path/code ошибок; при ошибке не скрывать текущие данные и не обещать частичного применения.
- [ ] После commit дать открыть новый профиль; имя/ID не зашивать в UI.
- [ ] К минуте 180 перейти на живой backend и пройти сквозной сценарий; контрактные несоответствия сообщить А1 с точным request/response.

Доказательство: новый профиль отображается без пересборки приложения; повторный импорт не удваивает историю; UI корректно обрабатывает 410/409.

### A3.4. Проверки и сдача — 180–270 минут

- [ ] Запустить build и Playwright: login, profile, немутирующая примерка, completion, HR login/import, новый профиль, fallback state.
- [ ] Отдельный E2E с живым backend и синтетической БД; route mocks разрешены только для изолированных тестов UI-состояний.
- [ ] Проверить клавиатуру, подписи полей, 390/768/1280 px в текущих Chromium/Firefox/WebKit; отсутствие обрезанных карточек/ошибок, работу touch и prefers-reduced-motion. Учесть минимальные браузеры Tailwind 4 из §3.
- [ ] Написать README по §17, используя проверенные команды А1 и результаты А2. Указать требования Docker/сеть первого запуска, AI_PROVIDER, серверный ключ OpenAI и API-бюджет, опциональный локальный режим, demo-пароли и непроверенную официальную схему.
- [ ] THIRD_PARTY.md содержит зависимости/версии/лицензии, модель, источники и реально применённые AI-инструменты; сведения взять у А1/А2, не выдумывать.
- [ ] Пройти чистый запуск по README в отдельном Compose project с отдельными томами; не удалять рабочую demo-БД. Согласовать имя проекта и порт с А1.
- [ ] Написать docs/DEMO.md: сценарий на 3 минуты из §17, ID фиксированных сотрудников, ожидаемые эффекты и честные ограничения.

Доказательство: `npm --prefix frontend run build`, `npm --prefix frontend run test:e2e`; рабочий сценарий после чистого запуска. Снимки экрана — дополнение к тестам, не замена проверки записей.

## Передача

В frontend не должно быть OPENAI_API_KEY, в том числе через VITE_*; все AI-запросы идут через backend.

А1 получает путь frontend/dist и сведения о proxy/static routing. Координатор получает рабочий README, сценарий защиты, проверенные команды и список незакрытых проблем. Не объявлять приложение готовым по одному красивому скриншоту.
