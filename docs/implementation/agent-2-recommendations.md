# Агент 2 — рекомендации, объяснения и проверка AI

Обязательное чтение: [ТЗ ШАГРА](../superpowers/specs/2026-09-23-shagra-design.md), особенно §7–10, §13–16. **Цель:** модель действительно выбирает шаги с учётом контекста, а система гарантирует корректность фактов и расчётов.

## Владение

backend/app/recommendations, backend/tests/recommendations; tools/evaluate_recommendations.py, tools/benchmark.py; data/acceptance; docs/AI.md; docs/validation/ai.json и latency.json. Не менять contracts, core, API-роуты, Python lock и frontend. Запросы зависимости/типа передавать А1.

## Поставки и критерии

### A2.1. Проверить реалистичность AI — 0–30 минут

- [ ] Начать загрузку qwen2.5:1.5b через доступный Ollama; не ждать готовности всего backend.
- [ ] Отправить короткий /api/chat со schema, получить choices и проверить длительность после прогрева.
- [ ] Сообщить координатору: модель доступна / загружается / аппаратно не укладывается, с измерением. Если есть более мощный доступный Ollama endpoint — проверить тот же протокол там.
- [ ] Создать независимые небольшие наборы Q1–Q3 по §14; ожидаемые решения задаются до настройки prompt.

Доказательство: реальный ответ модели, параметры вызова и время. Успешная загрузка весов сама по себе не доказывает качество рекомендаций.

### A2.2. Детерминированная часть — до 90 минут

- [ ] Реализовать build_candidates из §9.3, пользуясь функциями core А1. До их поставки писать тесты по контракту, не вторую реализацию формул.
- [ ] Сортировка score/target_gain/event_id; shortlist <=8 с обязательным максимальным target_gain; причины пустых состояний в точном порядке §9.1.
- [ ] Включить requested preferred_type и excluded_event_ids; никаких сохранённых выводов о характере сотрудника.
- [ ] Реализовать fallback с честным source. Проверить Q1–Q6 и граничные пустые случаи.

Доказательство: `python -m pytest backend/tests/recommendations -q`; результат детерминирован и не использует ID конкретного контрольного сотрудника в логике.

### A2.3. Модель и доказательства — до 150 минут

- [ ] Реализовать async OllamaProvider и RecommendationService с контрактами §9.3.
- [ ] Передавать alias C1…C8 и факты, schema, prompt_version=1; вход <=12 KiB, num_predict=256.
- [ ] Валидировать длину choices, уникальность, membership, reason_codes и сохранение максимальной пользы в выбранном наборе. При ошибке отклонять весь ответ.
- [ ] Собирать обязательные GRADE_TARGET/SKILL_GAP/HISTORY и проверяемые refs кодом. Свободный текст модели не показывать.
- [ ] Проставлять comparison_event_id по алгоритму §8.3; сами числовые сравнения UI получает из API preview.
- [ ] Добавить semaphore=1, 8-секундный общий timeout и кэш §8.4; тесты неизвестного ID, prompt injection, timeout, cache invalidation.

Доказательство: валидный LLM-путь, валидный fallback-путь и Q7/Q8/Q16. Тесты ошибок используют FakeProvider, не реальные восьмисекундные паузы.

### A2.4. Проверка качества и задержки — 150–240 минут

- [ ] Передать сервис А1 для интеграции, А3 — перечень пользовательских source/status.
- [ ] Прогнать Q1–Q3 с настоящей моделью и сохранить выбранные события/source/время; не засчитывать fallback как AI-успех.
- [ ] Проверить три фактора объяснения на каждом выбранном событии; refs существуют, числа совпадают с core.
- [ ] evaluate_recommendations читает собственные fixtures и запускает сервис напрямую с настоящим provider; HTTP не обязателен.
- [ ] benchmark работает с живым API, входит как HR с env-паролем, отправляет Origin, получает текущие версии, выполняет 30 запросов; cache misses обеспечить разными профилями, hits измерить отдельной серией.
- [ ] В отчёт записать model, prompt_version, SHA, машину/режим CPU или GPU, p50/p95/max, llm_success_count, fallback_count и причины; исходные персональные данные не публиковать.
- [ ] Написать docs/AI.md: роль модели, формула эвристики, ограничения, реальные результаты и способ воспроизведения.

Доказательство: живые Q1–Q3 <10 секунд каждый; минимум 90% валидных LLM-ответов в серии 30 и p95<10 секунд. Если критерий не достигнут, отчёт содержит фактический результат и статус «не выполнен».

## Передача и границы

А1 получает сервис, исключения и конфигурацию. А3 получает готовые evidence и режимы, не должен рассчитывать рейтинг. Метод не обещает повышения/снижения оттока и не прогнозирует причины пропусков. Передать А3 сведения о модели, лицензии и источниках для THIRD_PARTY.md.
