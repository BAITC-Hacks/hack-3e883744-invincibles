# Упрощённый интерфейс, языки и две темы

23.09.2026. Реализация последующего запроса пользователя: RU/KZ/EN, переключаемая светлая/тёмная тема, более крупный и понятный GUI, сохранение необходимых сценариев и push. Это новая версия рабочего frontend. Прежние плотные макеты из `../redesign/` сохранены как история; они не объявляются принятыми эталонами для этой изменённой композиции.

## Что изменено

- Языки RU / KZ / EN и кнопка темы доступны в шапке приложения и на входе. Выбор хранится в localStorage; при запрете хранилища переключение продолжает работать в текущем посещении. KZ соответствует стандартному `lang=kk`. Тема устанавливается до первого отображения страницы.
- Основной текст увеличен до 16 px, заголовки и показатели — до 20–32 px. Основные кнопки не ниже 48 px, интерактивные иконки — 44 px. Локальные IBM Plex Sans/Mono поддерживают кириллицу.
- `/me` показывает готовность навыков и одну главную рекомендацию. Альтернативы, evidence и технические refs раскрываются отдельно. `/me/skills` содержит поиск, фильтры, уровни и интерактивную матрицу; `/me/history` — поиск и страницы истории. Переходы между этими разделами сохраняют исключения и не запускают повторный запрос рекомендаций.
- Меню находится слева на компьютере, в компактной боковой полосе на планшете и внизу на телефоне. Аккаунт и выход отделены от навигации. HR-профиль использует локальные разделы через `?tab=`.
- Примерка сначала показывает выбранный шаг; сравнение с B включается явно. Обе колонки используют одну исходную версию и одинаковый набор строк навыков. Подтверждение называет вариант A; повтор после сетевой ошибки использует прежние Idempotency-Key и тело. При 409 примерка закрывается и профиль обновляется.
- HR сначала видит поиск сотрудника, три показателя и топ-5 дефицитов. Подробные таблицы раскрываются отдельно, видна одна выбранная таблица. Вкладка, поиск, сортировка и страницы хранятся в URL. Мобильные строки раскрываются без прокрутки всей страницы. Возврат из найденного профиля сохраняет URL исходного HR-поиска.
- Импорт показывает этапы «Файлы → Проверка → Применение». Результат занимает место только после проверки. У каждого файла одно имя и размер; validate/commit разделены, предупреждение о полной замене профиля сохранено.
- Монолит App.tsx разделён на app/pages/features/entities/shared; HTTP-клиент и контрактные типы находятся в shared/api, переводы и настройки — shared/lib, стили — shared/styles. Глобальные классы используют `sh-`; прежний конфликт `table-caption` устранён.

## Воспроизведение проверок

```powershell
npm --prefix frontend run build
npm --prefix frontend run test:e2e -- --workers=3
$env:LIVE_BASE_URL = 'http://127.0.0.1:8091'
npm --prefix frontend run test:e2e:live
```

Для живого теста запустить backend на указанном origin с отдельными DATABASE_PATH и SESSION_SECRET_PATH и собранным frontend/dist. Фактическая проверка использовала новый `runtime/a3-simple-<uuid>.sqlite3`, APP_ORIGIN=http://127.0.0.1:8091 и пустой OPENAI_API_KEY в дочернем процессе. Основная БД и .env не изменялись. Повтор теста создаёт отдельный импортированный ID.

Браузерный набор содержит 15 сценариев × Chromium/Firefox/WebKit: сохранение языков/темы; навигация без повторного AI-запроса; немутирующая примерка; сравнение; focus trap/Escape/возврат фокуса; выполнение; идемпотентный повтор после сетевой ошибки; stale context; retry рекомендаций; сохранение исключений; HR/импорт; ширины 320/390/768/1280/1440; CSS zoom=2; reduced motion; контраст; loading/empty. Контраст проверяется для 20 пар цветов в каждой теме: текст ≥4,5:1, значимые границы ≥3:1. UI- и live-прогоны используют отдельные каталоги артефактов, чтобы не удалять trace друг друга.

Итог после объединения параллельного UI-слоя из `origin/main` (`44f5865`): `npm ci` и сборка успешны, **45/45 браузерных тестов и 1/1 живой сценарий прошли**. Повтор живого сценария выполнен на новой `runtime/a3-simple-final-<uuid>.sqlite3`. Финальные PNG повторно получены на объединённом коде. Сохранены общие Button/Field и совместимые точки входа типов/диалога; HR отображает человекочитаемые названия ролей, когда они присутствуют в API. Старые моноязычные стили из параллельной поставки не импортируются поверх активной темы.

## Языковые и проверочные границы

Все элементы управления и сообщения клиента имеют RU/KK/EN. Каталог выбирает `ru`, `kk` или `en` из API; если нужного поля нет, использует доступное название. В текущем синтетическом ките поле kk часто пустое, поэтому в KZ интерфейсе названия таких активностей остаются английскими и есть пометка. Серверные evidence и диагностические ошибки импорта сохраняются на языке источника; произвольных замен `Grade.*`/`EventType.*` нет. Исправление исходного evidence остаётся зависимостью A2. Имена HR-ролей должны поступать из API; неизвестные названия не выдумываются.

Смена языка/темы не меняет API-контракты, профиль, историю или расчёты. Покрытие считается сервером и не называется вероятностью повышения. Эти проверки не подтверждают работу физического iPhone, экранной клавиатуры, браузерного меню zoom или реального LLM с ключом. Проверка масштаба выполнена через CSS zoom=2; WebKit запущен как браузерный движок на Windows. Compose и backend-логика в этой задаче не менялись.
